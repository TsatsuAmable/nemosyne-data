# PT2B known-answer oracle and metamorphic corpus adversarial contract

**Date:** 2 September 2026  
**Base:** `main@dbffb6bb8b1f348403ccf24f704936b07aeb60c2`  
**Branch:** `feat/pt2b-known-answer-oracles`  
**Status:** PRE-IMPLEMENTATION ADVERSARIAL CONTRACT

## Purpose

PT2A made corpus identity and measurement semantics governable. PT2B makes a bounded subset of expected quantities independently executable and adds the first new corpus families required by `nemosyne-data#3`.

The tranche covers:

- one aggregate known-answer fixture;
- one distribution known-answer fixture;
- row-permuted and irrelevant-column metamorphic variants of both;
- one explicit zero-variance NIL/abstention fixture;
- an independent reference verifier that imports no Nemosyne application/runtime code;
- explicit representation expectation and metamorphic metadata.

Density and relationship-graph fixtures remain PT2C rather than being squeezed into the same review surface.

## Review finding inherited from PT2A

Comparing the PT2A contract back to issue #3 exposed two gaps that must be fixed forward here:

1. a known answer had no machine-readable operation, so an external consumer could verify artifact identity but not generically re-compute the claimed quantity;
2. the catalogue did not yet carry explicit representation expectation or metamorphic lineage metadata.

PT2B extends the v2 schema rather than creating a parallel manifest format.

## Authority boundaries

- Reference checks live wholly inside `nemosyne-data` and may use Node standard-library code only.
- Reference checks must not import, call, copy output from, or shell into Nemosyne/Moneta/Rust/WASM production code.
- The corpus states expected evidence and representation obligations; it does not become representation-selection authority.
- Family labels are evidence labels, not a frozen list of layout candidates.
- Metamorphic variants must be distinct byte artifacts while preserving the declared scientific checks of their base dataset.

## Fixture tier

PT2B introduces a 16-row `fixture` tier. It is intentionally tiny so exact oracles and metamorphic invariants remain cheap enough for every corpus CI run. Scale qualification remains the role of the existing smoke/small/medium/large/xlarge tiers.

## Machine-readable reference checks

A known answer may carry a `verification` object. PT2B supports these bounded operations:

- `row-count`;
- `distinct-count`;
- `sum`;
- `mean`;
- `group-sum`;
- `population-variance`;
- `quantile-r7` with explicit probability;
- `tail-count` with explicit comparison operator and threshold.

Expected values remain in the catalogue and are compared under the structured PT2A tolerance contract. The reference implementation computes actual values from artifact bytes and never derives expected values from Nemosyne output.

## Metamorphic contract

Each metamorphic variant identifies its governed base dataset and one or more transforms. PT2B supports:

- `row-permutation`;
- `irrelevant-column-addition`.

The catalogue validator must prove that a variant preserves the base dataset's machine-verifiable known-answer signatures. The independent reference verifier must then re-compute those checks on the variant artifact itself.

## Representation expectation contract

PT2B adds a deliberately small evidence-level contract:

- `eligible`: one or more semantic representation families are evidence-supported;
- `abstain`: the dataset is designed to require abstention rather than a forced representation;
- `surface-alternatives`: multiple families should remain explicit alternatives.

For the NIL fixture, all quantitative columns have population variance zero. Its expected disposition is `abstain` with reason code `zero-variance-quantitative-signal`.

## Falsifiers

Reject or fix forward if any of these occur:

1. Reference verification imports Nemosyne production/runtime code.
2. A declared machine-verifiable check can pass without reading its artifact.
3. An expected quantity is generated by the implementation under test rather than independent derivation.
4. Row permutation changes an aggregate/distribution expected result without validation failing.
5. Adding the irrelevant label column changes a preserved expected result without validation failing.
6. A metamorphic variant points to a missing, candidate or self base dataset.
7. A metamorphic variant silently changes the base known-answer signature.
8. A variant reuses the base artifact digest despite different bytes.
9. The NIL fixture can be marked `eligible` while its contract says `abstain`.
10. An `eligible` representation expectation has no family evidence label.
11. A `quantile-r7` check omits or accepts an out-of-range probability.
12. An approximate comparison bypasses the PT2A tolerance rules.
13. Regenerating PT2B fixture artifacts changes checked-in bytes.
14. CI verifies only catalogue shape but does not execute the independent known-answer verifier.

## Exit evidence

- checked-in PT2B fixture bytes reproduce deterministically from the generator;
- catalogue/digest validation is green on exact head;
- independent known-answer verification is green on exact head;
- every metamorphic variant recomputes preserved checks from its own bytes;
- NIL representation expectation is explicit and machine-validated;
- final adversarial review records ADOPT/TARGETED/REJECT before merge.
